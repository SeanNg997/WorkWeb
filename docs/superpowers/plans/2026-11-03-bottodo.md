# BotTodo Implementation Plan

> **For agentic workers:** Implement task-by-task on branch `BotTodo` from `main`. Open a PR when done. Prefer frequent commits.

**Goal:** Add a Bot TODO module that read-only renders two markdown files from the data dir and posts JSON webhooks via a server proxy, matching WorkWeb’s existing UI.

**Architecture:** Extend `index.html` (sidebar, page, settings, poll/render) and `server.js` (read md + proxy webhook). Persist webhook URL like other settings; whitelist desktop setting key if needed.

**Tech Stack:** Existing WorkWeb — Node `server.js`, single-page `index.html`, `marked`, Electron settings bridge.

## Global Constraints

- Branch name: `BotTodo` (from current `main`).
- Do not change unrelated modules.
- Match existing sidebar/button/theme patterns; premium aesthetic for float islands.
- Fixed files: `bot-todo/todos.md`, `bot-todo/schedule.md` under data dir.
- One webhook URL in settings “Grok Bot” section, placed before data-dir section.
- JSON payloads exactly as in the attached design spec.
- Poll ~3–5s only while Bot TODO page is active.
- Anniversaries out of scope.

## File map

- Modify: `server.js` — ensure `bot-todo/` helpers; `GET /api/bot-todo`; `POST /api/bot-todo/webhook`
- Modify: `index.html` — CSS, sidebar item, `#page-bot-todo`, settings block, JS (load/poll/render/send)
- Modify: `electron/main.js` — allowlist webhook setting key if desktop settings use allowlist
- Modify: `document.md` — short section documenting the module
- Add: `docs/superpowers/specs/2026-11-03-bottodo-design.md` and this plan under `docs/superpowers/plans/` (copy from uploads if present)

### Task 1: Backend read + webhook proxy

**Files:** `server.js`

- [ ] Ensure data dir has `bot-todo/`; missing md files return empty strings.
- [ ] `GET /api/bot-todo` → `{ todos, schedule }` UTF-8 text.
- [ ] `POST /api/bot-todo/webhook` accepts `{ type, text }`; loads webhook URL from request body field `webhookUrl` **or** from a small config file under data dir if frontend also persists there — prefer: frontend sends `{ type, text, webhookUrl }` for browser mode simplicity OR server reads desktop-persisted value. **Chosen:** frontend POSTs `{ type, text }` and also stores URL client-side; for server proxy pass `webhookUrl` in the POST body so server need not own settings store: `{ type, text, webhookUrl }`. Validate URL is http(s). Forward JSON `{ type, text }` to webhook. Return upstream status or clear error.
